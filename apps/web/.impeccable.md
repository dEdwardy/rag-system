## Design Context

### Users
- Primary user today: the project owner using this as a personal knowledge workspace.
- Near-term expansion target: a small internal team, but not a broad self-serve SaaS audience yet.
- Core job to be done: move from ingesting documents or source URLs to asking grounded questions, inspecting traces, and tuning assistant behavior without losing confidence in what the system is doing.
- Product expectation: the interface should reduce setup ambiguity, make next actions obvious, and keep retrieval / answer context legible instead of hidden.

### Brand Personality
- Three-word personality: calm, professional, trustworthy.
- Emotional goal: the product should feel like a dependable engineering workspace rather than a flashy AI demo.
- Tone should stay direct, competent, and low-drama, with enough warmth to avoid feeling like a cold admin console.

### Aesthetic Direction
- Dark-first workspace interface.
- Reference direction: Linear / Raycast for focused, disciplined tool feel; Vercel / Supabase for credible developer-product polish.
- The product should feel like a serious knowledge operations console with clear hierarchy and strong readability, not a decorative showcase.
- High contrast matters more than ornamental effects, and dense information is acceptable only when the reading order stays obvious.

### Design Principles
1. Make the next action obvious. Empty states, setup states, and transitions should always tell the user what to do next.
2. Prefer trust over spectacle. Strong contrast, clear labels, grounded status copy, and traceable system behavior matter more than visual novelty.
3. Keep the workspace calm. Avoid noisy motion, decorative gradients, and attention-grabbing effects that make the product feel like AI marketingware.
4. Preserve professional density without becoming a generic backend. Information can be rich, but hierarchy, grouping, and scan order must stay intentional.
5. Avoid four failure modes: AI shell aesthetics, generic enterprise admin styling, toy-demo softness, and over-specialized hacker-only tooling.
