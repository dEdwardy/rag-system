# 自主执行工作流清单

## 目标

适用于这种协作方式：

- 用户给目标
- agent 自己完成排查、开发、调试、验证
- 尽量不中途暂停
- 最后只给高层总结

## 默认原则

### 1. 先做前置风险扫描

开始前先快速判断是否存在：

- 权限问题
- 环境缺失
- 远程写入风险
- 破坏性操作
- 必须由用户拍板的分叉
- 必须由用户提供的外部条件

如果后面大概率会卡住，尽量在一开始一次性说明。

### 2. 能自己查的，就自己查

优先自己完成：

- 读代码
- 搜索仓库
- 跑命令
- 看日志
- 跑测试
- 做只读排查
- 做最小验证

不要默认让用户去中转技术信息。

### 3. 不把用户当传话器

尽量避免：

- 让用户去看文件再转述
- 让用户去跑命令再贴结果
- 让用户去做本来 agent 能做的检查

只有在 agent 真的做不到时，才把任务抛给用户。

### 4. 默认闭环执行

如果任务本质上是：

- 修 bug
- 做优化
- 做排查
- 修类型错误
- 跑验证

并且没有高风险阻塞，就默认直接做完整闭环：

1. 诊断
2. 改动
3. 验证
4. 总结

### 5. 只在必要时打断用户

适合打断的场景只有：

- 破坏性操作
- 生产风险
- 远程写入
- 权限不足
- 业务选择会明显影响结果

### 6. 最后讲结果，不强迫用户理解技术细节

结束时重点告诉用户：

- 做了什么
- 为什么这么做
- 验证结果如何
- 剩余风险是什么

默认用高层总结，不要求用户理解细节。

## 一句话总结

能自己闭环完成的任务，就自己闭环完成。  
把风险前置，把中转减少，把总结留到最后。
