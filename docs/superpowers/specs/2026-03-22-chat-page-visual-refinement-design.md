# Chat Page Visual Refinement Design

> 文档角色：`task-spec`
> 当前使用方式：用于记录 2026-03-22 这轮 `Chat` 页面视觉收口的设计决定，范围仅限 `PC Web` 聊天页。

## Task Identification

当前仓库已经完成 `PC Web chat experience polish` 的第一轮主链路，包括流式问答、基础聊天工作区和引用侧栏。

这次增量不再处理流式协议或跨页面统一改版，而是基于当前实现做一轮更收敛的视觉判断与落地：

- 以 `ui/version-a-constrained.*` 作为主方向
- 吸收 `ui/version-b-creative.*` 中少量对聊天工作区真正有帮助的优点
- 只改 `Chat` 页面，不改全局主题

## Goal

让当前 `Chat` 页面更接近“稳定、可信、可连续使用的工作台”，而不是继续停留在“多个并列卡片拼起来的 MVP 页面”。

用户应明显感受到这些变化：

- 页面主次更清楚
- 中间消息工作区更聚焦
- 左侧会话列表更像会话导航
- 右侧引用区更像证据面板
- 顶部说明区更克制，不抢主内容

## Non-Goals

- 不切换到深色主题
- 不更换品牌主色到 indigo / purple
- 不重做 `AppShell`
- 不同步改造 `Documents` / `Knowledge Base` / `Assistant`
- 不新增移动端适配
- 不改动聊天数据结构和 API 行为

## Current State

当前 [ChatPage.tsx](../../../apps/web/src/pages/chat/ChatPage.tsx) 已经具备：

- 左侧会话列表
- 中间消息流与输入区
- 右侧最新引用区
- 流式回答状态

问题不在于功能缺失，而在于视觉组织仍偏“卡片堆叠”：

- 顶部 hero 存在感偏强，占用了工作区注意力
- 中间消息区与输入区仍然像两张分离的业务卡片
- 左右两栏的交互单元更像普通按钮/卡片，而不是高频使用的导航/检查面板
- A 的稳重方向还没有完全落地，B 的“中心工作区聚焦”优点也还没有被借过来

## Chosen Direction

采用 `A 为主、B 为辅` 的混合方案：

### 保留 A 的部分

- 浅色基调
- teal 品牌主色
- 温和边框和低对比层次
- 低风险三栏信息结构
- 适合当前产品阶段的“专业工具感”

### 吸收 B 的部分

- 让中间聊天区成为真正的主工作面
- 让输入区更有焦点和操作感
- 让右侧引用卡片的信息层次更紧凑
- 让会话列表选中态和扫描效率更强

### 明确不吸收的部分

- 深色背景
- 大面积发光效果
- 全局品牌改色
- 过强的装饰纹理
- 明显偏概念稿的视觉语言

## Visual Thesis

页面应呈现为一个“浅色研究控制台”：

- 主体稳定、清晰、克制
- 中间区域更像连续工作面
- 两侧区域更像辅助导航和证据检查器
- 装饰存在但不过度

## Layout Strategy

继续保持三栏结构，但重新定义权重：

### 1. 顶部引导区

保留，但显著收紧：

- 从“显眼 hero”收敛为“页面上下文条”
- 只保留页面身份、当前助手、在线/模型状态、简短目标提示
- 视觉上不再是页面最重的块

### 2. 左侧会话栏

从“按钮集合”调整为“会话导航列表”：

- 更清楚的选中态
- 标题、时间、消息数的层级更明确
- 新建会话入口保留，但不应压过列表本身

### 3. 中间工作区

这是本次最重要的区域：

- 弱化“卡片感”，强化连续阅读和连续输入
- 消息区与输入区形成同一工作流，而不是两张割裂面板
- 助手消息、用户消息、流式中消息、错误消息要更容易一眼区分

### 4. 右侧引用区

从“最新引用卡片列表”收口为“当前回答证据面板”：

- 更强的文档标题层级
- 更紧凑的 chunk / page / section 信息
- snippet 优先服务扫描，而不是装饰
- trace 行为保留但次级化

## Interaction Strategy

只保留少量有效交互反馈：

- 会话项 hover / active 更清楚
- 新消息与流式消息有轻微状态反馈
- 输入区 focus 和提交态更明确

不新增重动画，不引入强装饰 motion。

## Testing

因为本轮主要是 `ChatPage` 结构与样式收口，验证应保持轻量：

- 现有 focused chat helper / stream state 测试不回归
- `pnpm --filter @rag-system/web build`

如果本轮提炼出新的纯函数，可补一个最小测试；否则不为视觉改动强行添加低价值测试。

## Documentation

如果最终实现明显改变当前聊天页呈现方式，应更新：

- `docs/current-progress.md`

`docs/current-dev-setup.md` 仅在新增或调整验证命令时更新。

## Acceptance Criteria

- 顶部区域明显更克制，不再抢占页面焦点
- 中间消息工作区成为页面最强视觉中心
- 左侧会话栏更像高频聊天导航，而不是普通按钮堆
- 右侧引用区的扫描效率高于当前实现
- 页面仍保持浅色 teal 主方向，与当前产品一致
- 不引入深色主题和全局设计语言切换
