## 二、怎么自己评估（15 分钟）

需要本地前后端已启动（`:3000` / `:5173`）。

```bash
# 1. 结构层：页面该有的状态分支在不在、有没有死链
pnpm --filter @rag-system/web audit:pages

# 2. 渲染层：12 条路由真跑一遍浏览器
pnpm --filter @rag-system/web smoke:routes

# 3. 交互层：三条关键路径
pnpm --filter @rag-system/web smoke:citation    # 引用徽标 → 来源面板
pnpm --filter @rag-system/web smoke:locale      # 中 ↔ 英 双向切换
pnpm --filter @rag-system/web smoke:reports     # 评测指标卡片（会真跑一次评测）

# 4. 静态层
pnpm --filter @rag-system/web test:guard        # 63 passed
pnpm --filter @rag-system/web typecheck         # 0 error
pnpm check:encoding                             # UTF-8 无 BOM
pnpm lint                                       # oxlint，0 error
```

**判断标准**：以上全部 exit 0，即"当前状态没有已知回归"。任何一条失败，看它在 `docs/web-acceptance-checklist.md` 里对应哪类缺陷。

浏览器脚本需要指定缓存的 Chromium：

```powershell
$env:SMOKE_CHROMIUM_PATH = "$env:LOCALAPPDATA\ms-playwright\chromium-1217\chrome-win64\chrome.exe"
```

## 三、功能正确性：修过什么，怎么证明修好了

这轮系统性审计一共修了 8 个问题。**每个都能对应到一条会失败的断言**，不是"我记得修过"。

| #   | 问题                              | 用户会怎么感知                   | 验证                                                                   |
| --- | --------------------------------- | -------------------------------- | ---------------------------------------------------------------------- |
| 1   | 拒答时把原始模型 JSON 当答案      | 答案框里出现 `{"answer":"",...}` | `apps/api/test/llm.test.js`（16 passed）                               |
| 2   | 复用历史答案返回原始 JSON         | 同一会话重复提问时出现 JSON      | `apps/api/test/reused-answer-content.test.js`（6 passed）              |
| 3   | 消息接口不返回 citations          | **引用徽标点了没反应**           | `apps/api/test/messages.service.test.js`（4 passed）+ `smoke:citation` |
| 4   | 评测表格 38 个中文 key 全是 `???` | 评测页表格显示问号               | `smoke:reports` 断言无 `??`                                            |
| 5   | 6 个英文 key 中文目录缺失         | 中文界面里冒出英文               | `apps/web/test/i18n-copy.test.js`                                      |
| 6   | 4 个源文件带 BOM                  | 编码规范问题，lint 报警          | `pnpm check:encoding` + `lint`                                         |
| 7   | 缺 key 静默回退英文               | 漏翻没人发现                     | dev 控制台警告 + 第 5 条测试                                           |
| 8   | 中文侧边栏分组标题与导航项同名    | 侧边栏连着显示两遍"工作区设置"   | `apps/web/test/i18n-copy.test.js`                                      |

**其中第 3 条值得单独说**：前两次修复都只在前端打补丁（加组件、补缓存字段），一直没生效。真正原因是**后端消息接口根本不返回引用数据**。这条说明：**症状在前端，根因可能在接口**。

## 五、明确没有评估的部分

不写"应该没问题"，这些都是**没验证过**：

- **键盘可达与焦点顺序**：需要人工 Tab 走查
- **颜色对比度**：需要工具或人工判断
- **移动端布局**：脚本只跑桌面视口
- **边界数据**：空库、超长标题、单文档、0 文档时的表现
- **并发 / 性能**：多个请求同时进行的表现

## 六、已知的工程债（不影响当前使用）

| 债                                                 | 影响                                                                        | 建议                                                         |
| -------------------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `AppShell` 自带一份文案表，与 i18n 字典重复        | 改一处容易漏另一处（第 8 个 bug 就是这么来的）                              | 合并到 i18n，独立一次提交                                    |
| `ReportCenterPage` 近 3900 行                      | 改动时回归成本高                                                            | 按"运行 / 结果 / 导出"拆文件                                 |
| `npx vitest` 在本机 Windows 会崩溃（`0xC0000005`） | 直接跑单测会莫名其妙失败                                                    | 统一走 `node scripts/run-test-file.mjs`                      |
| 会话列表曾被测试数据污染（254 条）                 | 侧边栏不可用                                                                | 已清理至 1 条（备份在 `tmp/conversations-backup.json`）      |
| **评测每跑一轮会为每道题各建一个会话**             | 254 条里有约 240 条来自评测运行（20 题 × 约 12 轮），跑几次评测侧边栏就满了 | 评测产生的会话不应进入用户会话列表，建议用独立状态标记或归档 |

## 七、对话页的一个待决策行为

当前行为：**打开对话页会自动接管最近一个会话**，新问题直接追加进去。

- 好处：连着追问很顺
- 风险：新问题可能被追加到**不相干的历史话题**下（实测中发生过）

另外 `messages.zh.ts` 里有一句 `发送新问题后会自动开启新的会话。`，**没有任何组件使用它**——文案描述的行为和实际行为相反。

这属于产品决策，需要拍板：保持现状 / 默认新会话 / 接管但顶部提示当前会话标题。
