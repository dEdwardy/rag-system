### 本次选择的单点增量（外部 source fetch 失败可观测性）
**问题点（visibility gap）**  
网络层 fetch 异常常只有通用信息（如 `fetch failed`），在 external source 失败诊断里不容易直接看出是哪个 URL 失败。

**实现（最小改动）**
1. `apps/api/src/infra/http/fetch-with-retry.ts`
   - 在 `normalizeFetchError()` 中，对**非 redirect 类**异常统一增强为：
     - `Fetch request failed for <sourceUrl>: <original message>`
   - 保持 redirect 路径现有语义不变（`Failed to follow redirect ...` 仍原样保留）。

2. `apps/api/test/fetch-with-retry.test.js`
   - 新增测试：`fetchWithRetry includes source URL in network failure error`
   - 通过 mock `global.fetch` 抛出 `TypeError("fetch failed")`，断言错误信息包含具体 source URL。

3. `docs/current-progress.md`
   - 记录本次最小增量与验证命令。

### 本次新增的“精确信号”
新增诊断信号是：  
**fetch 网络失败时，错误文本现在显式带 source URL 归因**，例如：

`Fetch request failed for https://example.com/source.xml: fetch failed`

这会直接提升 external source fetch 失败时的定位效率（无需再从上下文反推是哪条 source URL 失败）。
