**Scenario fixed (stale-state / missed-update):**  
Legacy external **web-page** documents with `sourceConfigJson = null` were failing re-sync early with `EXTERNAL_SOURCE_CONFIG_INVALID`, even when `sourceType=web_page` and `sourceName` URL were still valid.

**Change:**  
During `POST /documents/:id/reindex` external re-sync parsing, if stored config is missing, backend now performs a narrow legacy fallback for web-page docs:
- reconstructs config as `{ kind: "web_page", url: sourceName }`
- continues re-fetch/finalize/enqueue path instead of failing immediately

No new source family, no retry policy rewrite, no connector/platform refactor.
