### Chosen stale-state scenario
Older external documents can have legacy `sourceConfigJson` shaped like:
- feed: `{ kind: "feed", url: "..." }` (missing `maxItems`)
- sitemap: `{ kind: "sitemap", url: "..." }` (missing `maxPages`)

Before this change, re-sync parse required numeric bounds and failed early with `EXTERNAL_SOURCE_CONFIG_INVALID`, so re-fetch never happened.

### Minimal concrete change made
1. **Recovery logic in config parsing**
   - File: `apps/api/src/modules/documents/documents.service.ts`
   - `parseExternalSourceConfig()` now accepts legacy-missing bounds for feed/sitemap and falls back to default bound `20`.
   - Added small helper:
     - `resolveExternalSourceBoundOrLegacyDefault(value)`:
       - number → use it
       - `undefined` / `null` → fallback `20`
       - otherwise invalid

2. **Focused regression test**
   - File: `apps/api/test/external-source-sync.test.js`
   - Added test:
     - `DocumentsService reindex recovers legacy feed config without maxItems by using default selection bound`
   - Verifies:
     - reindex creates `external_resync` run
     - fetch is called with `maxItems: 20`
     - document proceeds through finalize + enqueue path (no early invalid-config failure)

3. **Progress doc update**
   - File: `docs/current-progress.md`
   - Added a small entry for this increment and validation snapshot.
