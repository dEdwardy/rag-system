### 本次最小改动（只做一个 edge case）
#### 改进点：`web page` HTTP 响应 content-type 边界处理
**文件：**
- `apps/api/src/infra/web-page/web-page.service.ts`

**行为改动：**
- 之前：`fetchWebPage()` 只接受 `text/html` / `application/xhtml+xml`，否则直接 `Unsupported web page content type`。
- 现在：增加一个窄 fallback：
  - 当 `content-type` **缺失**或为 `text/plain` 时，
  - 如果响应体“看起来是 HTML”（`<!doctype html>` / `<html>` / `<head>` / `<body>` / `<title>`），
  - 则继续走现有 HTML 提取逻辑（不再直接失败）。

**保持不变：**
- 显式非 HTML 类型仍严格失败（例如 `application/pdf` 仍报 unsupported）。
