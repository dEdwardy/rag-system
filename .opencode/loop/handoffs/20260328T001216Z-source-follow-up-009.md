### Minimal increment implemented
I added an **atomic version-guarded write** for external source finalize/failure updates.

#### Core change
In `DocumentsService`, external writes now use:

- `updateMany({ where: { id, version }, data })`

instead of only “check current version first, then blind update”.

If `updateMany` returns `count=0`, code keeps the existing stale-run behavior:
- mark run as skipped with `EXTERNAL_SOURCE_RUN_SUPERSEDED`
- do not apply stale response data

This closes a race where:
1. old external fetch result returns late,
2. newer resync already bumped `version`,
3. old response previously could still overwrite between check/write timing.

### Exact freshness behavior protected
**Protected edge case:** concurrent external re-sync stale response overwrite.

Now, stale finalize/failure payload from version `N` cannot overwrite document state for active version `N+1` (or newer), because write requires `(id, version=N)` to still match at write time.
